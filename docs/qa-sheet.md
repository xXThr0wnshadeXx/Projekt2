# Judge Q&A

Each answer is one sentence; the evidence column is what to open if asked. TODO means the evidence is still missing, not permission to improvise a number.

| Question | One-sentence answer | Evidence to have ready |
|---|---|---|
| Isn't this just ChatGPT? | Glance is built around understanding a page and confirming the student's own dictated maths, with a no-solving contract, rather than an open-ended chat. | [Product flow](../README.md), [integrity work and known gaps](https://github.com/xXThr0wnshadeXx/Projekt2/pull/228); avoid blanket claims about every chatbot configuration. |
| Can students use it to cheat? | We intend to refuse answers and hints, but known output gaps and the instructor lock still need validation before any institution approves an exam configuration. | TODO: demonstrate a refused “what's x?” on the deployed build and an instructor-controlled lock from [#189](https://github.com/xXThr0wnshadeXx/Projekt2/issues/189); [#188 scope](https://github.com/xXThr0wnshadeXx/Projekt2/pull/228) records unresolved channels. |
| What if the photo is bad? | The intended flow gives framing guidance and asks for a clearer page instead of pretending uncertain maths is reliable. | [Camera work #198](https://github.com/xXThr0wnshadeXx/Projekt2/issues/198), [capture-fidelity tests](../tests/e2e/capture-fidelity.spec.ts); TODO: live poor-photo trial with the deployed build. |
| How is it different from Equatio or a screen reader? | Equatio already documents image reading and speech input, while Glance's focus is the complete independent page-to-work flow, whose comparative advantage we have not measured. | [Sourced comparison](pitch.md#what-we-can-compare-today); TODO: shared-worksheet trial with the specified screen reader and Equatio. |
| Have blind students used it? | We do not yet have a recorded real-student session in our evidence ledger. | [Proof log](proof-log.md); TODO: consented trial, role, task, outcome and permission to quote; label teammate demonstrations. |
| What does it cost to run? | We have not verified a cost per page or spoken line, so we will measure actual provider usage on a defined workload before quoting a price. | TODO: dated request-usage report, model and provider prices, audio duration, retries and total cost divided by completed pages or lines; no synthetic estimate presented as actual spend. |
| Where does student data go? | Images and audio go to OpenAI for processing and session work stays in the browser, while provider retention and the deployed logging configuration still need review. | [Privacy description](../README.md#privacy), [capture route](../backend/app/routes/capture.py), [spoken route](../backend/app/routes/spoken.py); TODO: verify current provider terms and hosting logs before making a retention promise. |
| Braille? | The project includes Nemeth output, but we are not claiming that a braille reader has validated this full workflow. | [Math exports tests](../tests/e2e/math-exports.spec.ts), [screen-reader record](screen-reader-pass.md); TODO: braille-reader validation on the target device. |
| Who pays? | Disability-services offices and schools are the proposed buyers, with funding and pricing still to be validated. | [Business hypotheses](BUSINESS.md), [proof log](proof-log.md); TODO: buyer interviews and written pilot interest. |
| What's next? | We need to complete and rehearse the independent voice flow, close integrity gaps and test it with consenting blind and low-vision students. | [North star #197](https://github.com/xXThr0wnshadeXx/Projekt2/issues/197), [demo gates](demo-script.md#before-calling-the-demo-ready), [real-user proof #186](https://github.com/xXThr0wnshadeXx/Projekt2/issues/186). |
